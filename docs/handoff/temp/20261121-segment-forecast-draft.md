# 波段預測：文獻對照與開發評估草稿

狀態：供 Hermes 審閱，尚未交 CC。本文是研究規格草稿，不是實作指令。預測輸出和下單策略分開。

**建議先用現有 XGBoost 與 LSTM 比較未來區間高低，不必等新增 Transformer。** 先補「預測一段」所缺的目標，再用同一組樣本檢驗價位結構與 K 棒是否帶來增益。新增序列架構優先評估 TCN；Transformer、GRU 和混合模型列在同一份候選清單，但各有用途，不一起塞進第一輪。

## 2. 輸入公式：原文與本案改寫分開

令 O、H、L、C 為 t 已收完 K 棒的開高低收。以下任何特徵在 t 尚未收棒時不可用。

| 分組 | 原文證據 | 本案做成積木時的規格 |
| --- | --- | --- |
| Custom／單根形態 | CSI 300 表2：全幅 H−L，實體 abs(C−O)，上影 H−max(O,C)，下影 min(O,C)−L，方向 sign(C−O)；原文是點數，再用訓練集 z-score 處理連續欄 | 先做點數版。占比版是本案自訂：各長度除以全幅；全幅為 0 時三比例設 0 並輸出 flat_bar=1；缺資料維持無效 |
| Custom／價格位置 | Kim 等 §4 比較加入兩個距界特徵，原文用預先給定的動態邊界，兩欄為 (U−C)/C 與 (C−D)/C（附錄 A 表 A1） | 自訂 rolling 版本：U=max(H[t−N:t−1])、D=min(L[t−N:t−1])（區間兩端均含，不含 t）；輸出 U−C、C−D、(C−D)/(U−D)。距離有號；相對位置可出界，U=D 時標為無效；不足 N 根不計。底層可用 TA-Lib MAX/MIN 加一根位移，合成仍列 Custom |
| Custom／跨棒結構 | [Hosseini 等（2025）§II-A/B、式(1)–(4)、表10](https://doi.org/10.1109/ACCESS.2025.3584251)：以 5% 變動找轉折，六個轉折價形成 11 個比例，例如 F1=(P6−P5)/(P2−P1)。演算法可讓當根充當暫時末點，不能視作六個已確認轉折 | 第一版只列簡單、自訂的 ΔH=H[t]−H[t−1]、ΔL=L[t]−L[t−1]，保留幅度與符號。轉折比例另列，門檻不照搬；若採已確認點，只自確認時刻起可用，分母為 0 視為無效 |
| 趨勢／均線 | [Chalkidis、Savani（2021）§3.2、表1](https://arxiv.org/pdf/2110.14914) 用正規化收盤報酬的 48/240/480 根 SMA，不是原價 SMA 斜率 | 原價斜率是本案自訂：SMA_N(C) 用 TA-Lib；斜率為 (SMA_N[t]−SMA_N[t−k])/k，單位點／根，需 N+k 根；先與價格結構組分開，便於單獨對照 |

Hosseini 原文式(1)–(4) 補列：F1–F4=(P6−P5)/(P[i+1]−P[i])（i=1…4）；F5、F6 分別用 P6−P3 除以 P2−P1、P3−P2；F7=(P5−P4)/(P3−P2)，F8=(P6−P5)/(P4−P2)；F9–F11 各取相鄰兩段的有號價差之比（F9=(P3−P2)/(P2−P1)，依序向後滑）。六點 [100,110,101,113,104,116] 的 F1–F3 約為 1.20、−1.33、1.00。

驗算（自訂）：前區間 U=104、D=97；當根 O=100、H=105、L=99、C=103。上距 1、下距 6、位置 6/7；實體／上影／下影的點數為 3／2／1，占比 1/2、1/3、1/6。若 C=105，上距為 −1，位置為 8/7，不能強制裁成 1。

## 3. 第一輪目標、樣本與模型

- **目標草案：未來 H 根最高、最低各離現在多少點。** y_high=max(High[t+1]…High[t+H])−Close[t]；y_low=min(Low[t+1]…Low[t+H])−Close[t]。兩項先各跑單輸出迴歸，Label 用 identity，Horizon 可設定；初測提案 H=5 根（15 根另作敏感度比較），單位明示為 bar，不假稱 15 分鐘。配對評估需同一組起點。高低「發生在第幾根」可另外定義 argmax/argmin，平手選首次，第一輪先不要求模型輸出。
- **同一條件比較。** 核心基準：只用訓練資料的高低偏移中位數，再加一個[區間持續性基準（Lin、Sun，2019 表4–6）](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0211709)：用截至 t 的已完成等長窗，相對該窗起點收盤的高低偏移；接著 OHLCV 的 XGBoost 和 LSTM；再一次加一組特徵，固定輸出、切分、種子與樣本遮罩。第一輪使用同一交易時段且時間格連續的樣本；未來窗不完整、跨切分邊界、跨盤或換約均排除。只用訓練資料估正規化參數。
- **驗收數字。** 上、下界各列 MAE（點數），另記上下估計顛倒的比例，先看兩邊是否優於同一基準。例：C[t]=100，未來三根最高價 [102,105,105]、最低價 [99,98,97]，輸出 +5、−3；若後續做時間目標為 2、3 根。這不是交易進出場，策略另驗。

## 4. 到交 CC 時，請一次評估的範圍

已唯讀檢查本機 registry：有 LSTM、XGBoost；XGBoost 程式已有 binary／multiclass／scalar regression 分支；現列出的 outcomes 是 simple_return、log_return、future_price，都是單一未來收盤或其轉換。既有 identity 可評估沿用；是否可讓新目標、點數單位和遮罩一路通到前端與 API，待 CC 核對，不以本機程式擅稱上線支援。

1. **目標與特徵。** 評估新增可配置的未來極值 Outcome（side=high/low、horizon 正整數；以兩個單輸出作業先比較），以及 §2 前三組 Custom 的重用、分類和缺值規則；均線斜率獨立列成本。交付一組含完整窗和不完整窗的驗算回傳。
2. **模型。** TCN 第一新增候選：window、channels、kernel_size、dilations、dropout、pooling、classification/regression；原文參考 5 blocks、[1,2,4,8,16]、kernel 3、channels 64、dropout .2、全序列平均池化。另一次列清 GRU（units、layers、dropout）與 Transformer Encoder（window、d_model、n_heads、layers、ffn_dim、dropout、positional encoding、pooling、task head，d_model 應可整除 n_heads）的重用與改動成本。混合模型先評估前置 CNN 能否獨立組合（channels、kernel、stride），不把每個組合寫成專用模型。
3. **接口。** 保留特徵、Outcome、Label、模型可分別選配；後端 registry/validator、UI 參數、API 同步列影響面。CC 評估時回覆「可直接用／需補／不相容」與原因；未來若獲准做，CC 提供 API/schema、分類與參數範例及已知限制，再由 MCP 驗收。
